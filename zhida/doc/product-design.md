## 1. 产品概述

### 1.1 背景

待办、日历、习惯类软件主要解决任务**记录与管理**。用户仍须自己：制定目标、拆解、排期、记录、调整、总结。门槛高，长期坚持难。

很多人不是没有目标，而是不会把目标变成每天可执行的行动。

本产品用 AI 把「想学什么」变成「学哪些模块、每天做什么」。

### 1.2 定位

理解学习目标 → 识别技能分类与学习模块 → 用户勾选确认 → 展开任务并排期 → 跟踪执行 → 识别偏差并动态调整 → 周期复盘。

核心流程：

```text
提出学习目标 → AI 分析技能分类 → 拆学习模块（难易度/学什么）
  → 用户勾选模块 → 生成任务并写入日历 → 每日执行
  → AI 跟踪 → 动态调整（需确认）→ 周期复盘
```

### 1.3 核心价值

1. 降低学习规划门槛  
2. 大目标拆成可选学习模块，再落到每日任务  
3. 减少排期与管理成本（确认前不写日历）  
4. 发现执行问题  
5. 按真实执行持续调计划  
6. **留存用户技能档案**，跨学习目标复用已掌握能力，避免每次从零规划  

**差异：** 传统待办帮用户管理任务；本产品帮用户管理**学习目标实现过程**，并把学过的技能沉淀为可复用档案。

## 3. 功能架构

七大模块：用户资料 · **技能档案** · 目标管理 · AI 计划生成 · 每日任务执行 · AI 动态调整 · 数据分析与复盘。

### 3.1 首页：今日计划

展示：日期问候、今日完成进度、待办任务、重要提醒、AI 今日建议、快捷加任务。

原则：打开后 **5 秒内**知道今天最重要的事。

### 3.2 目标管理

自然语言创建目标，例如：

> 我想在 60 天内学会 Python，能独立完成一个数据分析项目，每天学 1 小时，周末 2 小时。

AI 提取：名称、描述、类型、起止、每日可用时间、基础水平、完成标准、优先级。生成分析后向用户确认。

建目标时须对照**技能档案**：已有相关技能则预填基础、跳过已掌握阶段；档案为空则引导用户勾选或简述当前水平。

状态：待规划 / 规划中 / 进行中 / 暂停 / 已完成 / 已终止。

**V1 限制：** 免费用户同时最多 **5** 个目标（进行中 + 待确认）；完成或删除后恢复名额；会员不限。

### 3.3 AI 目标拆解

三级结构：**目标 → 阶段 → 任务**。

任务字段：名称、说明、预计耗时、优先级、所属阶段、前置任务、关联技能、完成标准、推荐资料（适用时）。

拆解前读取用户技能档案；已达目标所需水平的技能对应阶段默认标记为「可跳过」，须用户确认后才跳过。

**规则：AI 计划必须经用户确认后才生效。**

### 3.4 每日任务

由目标计划自动生成。状态：待开始 / 进行中 / 已完成 / 已延期 / 已取消。

支持：完成、改时间、改内容、暂停、延期、手动添加。

### 3.5 AI 动态调整（核心差异）

未完成时**禁止**简单整日顺延。需分析：原因、时间、难度、前置知识（对照技能档案）、优先级变化；再生成新计划。

调整须包含：调整前/后计划、原因、用户确认、历史版本可回滚。

**V1：不允许 AI 未经确认自动改未来全部计划。**

### 3.6 每日复盘 / 每周复盘

日：完成量、投入时间、问题、明日建议。  
周：完成率、阶段进度、延期统计、完成预测、下周计划、改进建议；可附带本期技能变化摘要。

### 3.7 用户技能档案（跨目标留存）

技能与目标**分离存储**。目标结束或换赛道后，已掌握能力仍保留，供后续规划与重规划使用。

#### 档案字段

| 字段 | 说明 |
|------|------|
| skill_name | 技能名，如 Python、Pandas、英语听力、深蹲 |
| domain | 领域：技术 / 语言 / 运动 / 认知 / 职业 / 其他 |
| level | 程度：0 未知 · 1 入门 · 2 会用 · 3 熟练 · 4 能教人 |
| status | active / archived |
| evidence | 证据来源摘要（哪次目标、哪些任务） |
| source | self_report / task_evidence / ai_suggest |
| confirmed | 是否经用户确认（未确认不得作为跳过阶段依据） |
| updated_at | 最近更新时间 |

#### 写入规则（优先级）

1. **用户自报**：建目标确认、技能页手动添加/改程度（最高优先）  
2. **任务完成证据**：关联技能的任务完成后，系统提出「是否升至某级」，用户确认后写入  
3. **AI 推断**：仅生成建议，**禁止静默改档**；确认后才落库  

降级：用户可手动下调；长期未使用不自动降级（V1），避免挫败感。

#### 读取时机

| 时机 | 用法 |
|------|------|
| 目标创建 / 拆解 | 预填基础；跳过已掌握阶段（需确认） |
| 延期重规划 | 判断是否前置不足，而非一律减量顺延 |
| AI 助手对话 | 作为长期上下文的一部分 |
| 周复盘 | 展示本期新增/升级技能 |

#### 阶段节奏

| 阶段 | 范围 |
|------|------|
| P0 | 目标上保留「当前基础」文本/枚举；拆计划时用上；**尚无独立档案表读写 UI** |
| P1 | 落库 `user_skills`；目标完成/阶段完成时引导确认写入；建目标时读取档案 |
| P2 | 「我的 · 技能」独立页；跨目标图谱；重规划强依赖档案；导出 |

## 5. AI Agent 工作流

V1 用**工作流**（LangGraph），不做多 Agent 自由协作。

| 工作流 | 要点 |
|--------|------|
| 目标创建 | 读技能档案 → 意图 → 提取 → 补全 → 可行性 → 拆解 → 计划 → 确认 → 落库 |
| 每日计划 | 有效目标 → 任务 → 可用时间 → 依赖 → 今日计划 → 冲突检查 → 保存 |
| 延期调整 | 未完成 → 原因 → 对照技能档案判前置 → 影响 → 重规划 → 新旧对比 → 确认 → 版本 |
| 周期复盘 | 周期数据 → 完成率 → 延期归因 → 进度判断 → 技能变化建议 → 总结 → 下周期计划 |
| 技能归档 | 阶段/目标完成 → 候选技能与建议等级 → 用户确认 → 写入/升级 user_skills |

原则：任务状态以数据库为准；重要调整需确认；**技能档必须以用户确认为准**；输出结构化 JSON；记录版本；识别信息不足与不可行。

## 6. 技术架构

| 模块 | 选型 |
|------|------|
| 前端 | 微信原生小程序 · 工程目录 **`zhida/wx`**（后续小程序开发均在此） |
| 后端 | Python 3.12 + FastAPI · 工程目录 **`zhida/server`** |
| 工作流 | **LangGraph**（目标拆解：提取→可行性→拆解→排期）；重规划仍为 LLM+规则；失败回落本地模板 |
| 库 | **MySQL**（本机 `ai_work_zd`，见 `.env`） |
| 缓存 | Redis（P1，可选） |
| 定时 | Celery / XXL-JOB |
| 模型 | 国内合规模型 API |
| 部署 | 国内云 + 对象存储 |

链路：小程序 → FastAPI → 业务服务层 → Agent 工作流 → 大模型。

**AI 不直接改库**，统一经业务服务层。定时任务在云端跑（日计划、提醒、复盘、过期检查、额度重置），不依赖小程序后台。

与票齐分立路径：`/miniprog/zhida/`（票齐 `/miniprog/piaoqi/`）。预留端口 **7102**。

## 7. 数据核心

| 表 | 说明 |
|----|------|
| users / user_preferences | 用户与时间偏好 |
| **user_skills** | **用户技能档案（跨目标留存）** |
| **skill_evidence** | **技能变更证据（目标/任务/来源/前后等级）** |
| goals / goal_stages | 目标与阶段 |
| tasks / daily_plans | 任务与每日计划（tasks 可挂 skill_id） |
| plan_versions | 计划版本 |
| task_records / goal_reviews | 执行与复盘 |
| ai_conversations / ai_usage_records | 对话与调用 |
| memberships | 会员 |

关键：

- 目标与任务分离；任务是独立业务实体，不只存在对话里  
- 调整必留版本  
- **技能与目标分离**；技能不只写在对话或目标「基础水平」字段里  
- 未 `confirmed` 的 AI 建议技能不得用于自动跳过阶段

## 10. 核心指标

不以首期下载量为主要判断。重点：

| 指标 | 目的 |
|------|------|
| 目标创建率 | 是否认可产品 |
| 计划确认率 | AI 计划是否有用 |

| 每周任务完成率 | 是否帮到执行 |

## 13. 产品定义

不是简单 AI 待办，而是长期围绕用户目标运转的**个人执行系统**。

传统：用户自订计划，软件记录。  
学习目标规划：用户提出想学的内容，AI 拆模块，用户勾选后排期执行，AI 按反馈持续优化，**并把已掌握技能留在档案里供下次复用**。

**竞争力不在用了哪个大模型，而在能否用执行数据真正提高目标完成率，并形成可累积的个人能力资产。**
