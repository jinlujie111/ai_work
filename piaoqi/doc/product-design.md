## 1. 产品本质

```text
（个人票夹 或 群组票夹）
拍发票 / 导入图片
  → OCR 识别关键字段（可手改）
  → 按日期 / 商户 / 金额入账
  → 同群组成员共享查看同一份数据
  → 筛选汇总
  → 导出 Excel（或复制表格）
  → 按次或月卡收费
```

**一句话：** 不是财务系统，是「报销前把票整理成表」；需要多人共用时，用**群组**看同一份票夹。

不做：对接税局申报、多级审批流、替用户报税。  
群组 ≠ 公司组织架构：只做「共享票夹」，不做部门树、角色审批。

---

## 1.1 群组（共享票夹）

**定义：** 一个群组对应一份共享票夹；组内成员看到的票列表、合计、导出范围一致（同一数据视图）。

| 项 | 规则 |
|----|------|
| 创建 | 任意用户可创建群组，创建者默认为**组长** |
| 加入 | 邀请码 / 邀请链接；组长可移除成员 |
| 可见性 | 组内成员可查看、检索该组全部票据 |
| 录入 | 组内成员均可拍照入组（票记录创建人，便于追溯） |
| 编辑/删除 | 创建人可改自己的票；组长可改/删组内任意票（首期简化） |
| 导出 | 组内成员均可按该组数据导出 |
| 退出 | 成员可退出；退出后不再看到该组数据 |
| 解散 | 仅组长可解散；解散后票数据按策略归档或仅组长可见（实现时二选一，默认：**仅组长保留为个人票**） |
| 与个人票夹 | 每张票属于「个人」或「某个群组」，不跨组共享 |
| 额度 | 识别/导出次数优先扣**操作者本人**额度；组长可后续加「组额度」（二期） |

**典型场景：** 小团队共用报销底稿、出差小组共记票据、夫妻/合伙人共用进项票夹。

| 代号 | 切口 | 首期 |
|------|------|------|

## 3. 真需求与边界

**真：** 票多、字段要抄进 Excel、月底补报销想不起来。  
**虚：** 想要一个「自动替我完成公司报销全流程」的系统。

差异：比备忘录相册好在「结构化 + 一键导出」；比用友/畅捷通轻，只做整理。

---

## 4. 功能范围（MVP）

### 做

1. 拍照 / 从相册选图（单张，多张可二期）  
2. OCR：金额、日期、商户名（失败可手填）  
3. 票夹列表：编辑、删除、按月筛选  
4. **群组：创建 / 邀请加入 / 切换「个人 | 某群组」票夹；同组看同一份数据**  
5. 导出 Excel（或 CSV）常见报销列（按当前票夹范围）  
6. 免费额度 + 按次 / 月卡  

### 不做（首期）

- 税局接口、电子税票全自动查验  
- 公司组织架构、多级角色、审批流  
- 群组内细粒度权限（只读成员、仅财务可见等）——首期组员权限相同  
- 手写白条强依赖  
- 与「执达」账号打通

## 5. 页面结构

| 页面 | 内容 |
|------|------|
| 首页 / 票夹 | 顶部切换「个人 / 群组」；本月票列表、合计、拍照入口 |
| 群组 | 我的群组列表、创建、邀请码/链接、成员列表、退出/解散 |
| 票详情 | 原图、字段编辑、所属票夹（个人或组名）、保存 |
| 导出 | 基于**当前票夹**选时间范围 → 生成表 → 转发/保存 |
| 会员 / 次数 | 剩余次数、开通说明 |

## 6. 数据模型（草案）

```text
User
  - openid, vip_expire_at, quota_remain, created_at

Group
  - id, name, owner_user_id
  - invite_code, created_at

GroupMember
  - group_id, user_id
  - role(owner|member), joined_at

Ticket
  - scope(personal|group)
  - user_id              # 录入人
  - group_id?            # scope=group 时必填；同组共享
  - image_url
  - amount, ticket_date, merchant, category?
  - raw_ocr_json?, status(draft|ready)
  - created_at, updated_at

ExportJob（可选）
  - user_id, group_id?
  - range_start, range_end, file_url, created_at
```

**查询约定：**  
- 个人票夹：`scope=personal AND user_id=当前用户`  
- 群组票夹：`scope=group AND group_id=当前组`（须已是 GroupMember）

## 7. 会员与支付

```text
免费：每月 N 张识别（如 10 张）+ 导出 1 次
按次：识别或导出增量包
月卡 ¥9.9～19.9：更高额度 / 无限导出（数值上线前再定）
```

- 个人主体：虚拟支付  
- 话术：整理工具，不提供报税与法律意见  
- 影像可删；默认少留长期原图（可配置仅留字段）  
- 进组即同意：组内成员可见你录入到该组的票图与字段（创建/加入时明示）

## 8. 后端与部署

- 与执达分立服务或同分域不同路径：`/miniprog/piaoqi/`  
- OCR：云厂商 OCR API；大模型仅作字段纠错备选  
- 云主机或微信云开发均可；预留端口 7101  
- 群组接口需校验 GroupMember，防止越权读他组票据  

---

## 9. 原则

| 原则 | 说明 |
|------|------|
| 只整理不成财务 | 不做账套与报税承诺 |
| 识别可改 | OCR 必须可手改 |
| 导出是价值点 | 没有导出就不收费叙事 |
| 隐私可删 | 票图含敏感信息；组内共享须明示 |
| 群组即共享票夹 | 同组同数据；不做审批与复杂角色 |
| 项目独立 | 不与执达混库 |
